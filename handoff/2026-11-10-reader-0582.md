# Accept the Galaxy Book2 Pro 360's reader (0582)

PR #NUMBER · Claude · 2026-11-10

## What changed
- `1c7a:0582` added to every reader check: the deb, rpm and Arch scripts, the Arch `PKGBUILD` template, `install.sh`, `fixpaths.sh`, the fprintd drop-in, the boot check and monitor, the Manager, the helper, `distro-driver-check.py`, and the export and import tools. Their messages name it, and say Galaxy Book2 Pro 360, Book4 and Book5.
- Docs: README, Supported hardware (a new row), How it works, the Manager guide, the untested-hardware guide, the issue templates, the release page and the package descriptions. PLAN.md, CHANGELOG.

## Why
- Issue #174: the driver keeps fingerprints on a Galaxy Book2 Pro 360's `0582` reader (930QED, firmware 9050.1.1.87), where the distro's driver lost them. The tester had to install it by hand, as the packages refused the reader. David chose to accept only readers with a confirmed report, not every reader the driver lists.

## Tested
- Each shell check, and the rpm `%pre` and Arch `prepare()`, with a fake Samsung and USB device: `05a5`, `05a1` and `0582` accepted, `0584` refused, and a Book3 with `0582` still refused.
- The Manager's, helper's and `distro-driver-check.py`'s checks the same way.
- `py_compile`, `bash -n`, the templates rendered, the release PKGBUILDs generated.
- Not here: a real install on a `0582`, and the driver itself, which only the tester has run.

## For the next person
- The tester used Fedora Silverblue, where the packages don't fit. Refusing immutable distros is a separate PR.
- The README title still says Book4 and Book5. David's call.
- The other readers the driver lists (`0583`, `0584`, `0586`, `0587`, `0588`, `05aa`) stay refused until someone reports one working.
